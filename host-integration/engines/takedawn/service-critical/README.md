# Checked recursive critical sections

This is dependency-free game-side compatibility code in `../service-kernel-pool/kernel_pool.rs`, using the unmodified GamePKG child-local services. It does not put the game engine in the trusted runtime or add a native import exception. Source kit, members and original function spans are pinned in `reference_inputs.json`; these are source-contract pins, not an executed original-C differential oracle.

## Original behavior and deliberate error boundaries

Pinned ordinals 291/277/294 initialize/enter/leave a per-key recursive critical section. Each consumes one four-byte stack argument. Success sets EAX to zero and advances ESP by eight (argument plus return address); other registers remain unchanged. The bridge validates the complete stack/context before committing CPU state. Errors leave the CPU state unchanged.

The original uses the guest address only as a key into a separate native shadow table: it never reads/writes the guest's 20-byte structure. Initialize is idempotent, including while held; Enter and Leave create shadows lazily. Null keys are no-ops after context validation. Nonzero keys are logical u32 identities, including unaligned/unmapped addresses, never host pointers. Checked probes preserve surrounding guest bytes.

The original default table has 4,096 entries and can silently return without synchronization when full. This implementation retains the existing host's **128 shared synchronization-object budget**, 128 domain rows and 32 outstanding logical wait slots. Exhaustion is explicit Busy, never unprotected success. The optional original `RECOMP_CS_MODE=single` debugging collapse is not implemented or enabled. Host-recursive ownership replaces diagnostic owner-site/thread counters, but original diagnostic logging is not reproduced. Invalid foreign/unheld release and abandonment explicitly deny rather than emulating undefined Win32 critical-section behavior or pretending recovery.

## Contracts

All operations return `Result<_,i32>`: Invalid=-1, Busy=-2, Failed=-3, Denied=-4, Unsupported=-5. These follow existing SDK errors; they are not guest NTSTATUS values. An unknown transport error may follow an accepted action and never permits blind replay.

- `Criticals::criticals_new(ram,&owned_shadow)` requires a creator-owned empty dedicated map in the live root/services graph. The domain owns a 2,624-byte CSD1 record and all transferred native mutex IDs. `criticals_borrow(ram,&map,id)` is a non-owning view with complete schema/root/service/map validation. `criticals_id`, `criticals_map_id`, `criticals_closed` expose identities/phase only.
- `critical_initialize`, `critical_enter`, `critical_leave` take `(&Criticals,&Shadow,&Memory,u32)`. Enter is recursive for the actual calling task/thread. Leave requires actual native ownership. Enter tries immediately, then waits in bounded 1,000 ms SDK slices while healthy; total logical acquisition has no invented timeout. It runs on a game worker, never the host window owner. Each slice checks live services and exact domain/wait bindings before and after the native call. Busy preserves one ACTIVE logical lease across all slices.
- `criticals_begin` returns retained `CriticalCreation`. Call `critical_create_publish` **once**, then `critical_creation_close`, including on error. Accessors preserve the native ID and transfer phase: 0 reserved, 1 private native ID, 2 domain transferred, 3 mapped, 4 published/existing. Close retires a private native prefix or retains a transferred prefix in the owning domain. It never reconstructs a supposedly failed allocation by replaying it.
- `criticals_wait_begin` returns retained `CriticalWait`. Call prepare once, then slices of 0..1,000 ms. `critical_wait_pending` distinguishes safe uncommitted Busy from a terminal Busy/error. `critical_wait_native_result` retains the actually observed native result separately from post-action service errors. Always close: a published wait becomes DONE for domain-owned reaping; an unpublished record is private cleanup. Actual acquisitions remain owned until Leave or actual task-exit abandonment, including a post-acquisition error. A caller must not synthesize an unlock merely because it saw an error.
- `criticals_counts` returns wrapping u32 enter/leave diagnostic counts. Entry increments once on logical lease publication, not per Busy slice. Invalid foreign leave is rejected before increment. Counts do not establish ownership.
- Creator-only `criticals_close` refuses ACTIVE waits, outstanding creation guards and held mutexes with Busy **before** marking the domain closing. Once allowed, it journals typed native retirement, removes exact owned mappings and reaps DONE records before releasing the domain. Call again after retryable cleanup failures; do not discard an incomplete owner. Cleanup after cancellation uses typed SDK retirement, not a denied state query as evidence of absence. Cancellation can leave root/table duties requiring outer runtime teardown.

CSD1 has root/services/map/creator at 8/16/24/32, closing at 40, counts at 48/56, 128 native/key-phase rows at 64 and 32 wait slots at 2112. A row binds its exact u32 key in the high 32 bits and state in the low 32 bits. Duplicate keys/IDs, mismatched phases and noncanonical counts/slots reject. CWL1 is 80 bytes: root/services/map/domain/native/task at 8..48, done at 56, sign-extended result at 64 and guest key at 72. Record bytes never authorize an arbitrary native ID without actual SDK type/ownership checks.

## Startup integration

`Startup::startup_prepare_with_criticals` explicitly creates **KIC5**, retaining the dedicated map and domain before context allocation. `startup_criticals` returns validated borrowed views. KIC5 is 96 bytes: the existing KIC4 root/services/registry/event-shadow/HTR/EVD/SSD at 8..56, CSD1 ID at 64, reserved-zero 72..88. Its critical map must differ from the event map. Shutdown joins actual startup jobs, closes context, drains CSD1 and then its map before existing synchronization domains/root teardown.

Older startup entry points retain KIC1..4. The three imports require KIC5 and reject older contexts with Unsupported. They do not become context-free supported calls. Private-image mode 84 reports 95 remaining imports with KIC5; legacy mode 79 still reports 98 with KIC4. Neither invokes the title entry point.

## Local qualification

Run `python3 check.py --app <app> --app-lib <current-rlib> --wine --evidence <new-directory>` and `../service-kernel-imports/check_sync.py` with `--mutations`. Verify the library with the app SDK identity tool first. The critical suite checks recursion, idempotent/lazy/null keys, unchanged guest bytes, real worker contention/cancellation/service revocation, wrong ownership/root/map, malformed records, quota exhaustion and retained cleanup. Six altered implementations must fail behavioral assertions. Full source is scanned before host bindings, all eight optimized game objects are audited before trusted linking, and even unused maintainer providers must be rejected.

Signed Linux32/64 fixtures execute under confinement; Windows32/64 signed outputs are built and audited, while standalone SDK components execute under Wine when requested. These tests establish no game entry, scene fidelity, physical Windows input, audible output or measured gameplay frame pacing. Files/thread creation/NT wait/APC paths, full generated Rust, renderer/media conversion and actual private-service launch remain required. The normal Burnout profile stays blocked.
